## 1. 需求分析

### 1.1 项目背景

在现代物流和供应链管理中，仓库作为物资流转的核心节点，其管理效率直接影响企业的运营成本和服务质量。传统的手工记账方式不仅效率低下、容易出错，而且在库存盘点、出入库记录查询和库存预警等环节需要大量人工操作，难以及时掌握库存动态。特别是在物资种类较多、出入库频繁的场景下，人工管理方式已无法满足现代仓库对精细化、规范化管理的需求。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的仓库管理信息系统。该系统基于单链表数据结构，支持用户登录验证、物资信息的增删改查、物资入库与出库操作、出入库记录管理、库存总览与预警等功能。系统采用菜单式交互界面，操作直观便捷；数据采用文件持久化存储，保证程序重启后数据不丢失。通过本系统的设计与实现，深入掌握单链表在实际业务场景中的应用方法。

## 2. 概要设计

### 2.1 数据结构设计

系统选择单链表作为核心数据存储结构，基于以下设计考量：仓库中的物资种类数量在系统运行期间是动态变化的，无法在编译期确定上限，使用固定容量的静态数组会造成空间浪费或容量不足的问题。单链表支持运行时动态申请和释放节点，可灵活应对物资数量的增减变化，无需预分配固定大小的内存空间。

系统采用四条独立的单链表分别管理不同类型的业务数据：用户链表（UserNode）、物资链表（MaterialNode）、入库记录链表（InRecord）和出库记录链表（OutRecord）。各链表有独立的全局头指针（g_users、g_materials、g_inbound、g_outbound），所有模块通过全局头指针访问对应链表，设计简洁清晰。

选择单链表而非双向链表的原因在于：本系统以「顺序遍历」和「尾部追加」为主要操作模式，单链表完全满足需求，且每个节点节省一个指针的内存开销（每节点少8字节）。删除操作通过「前驱指针法」实现，无需双向链表的额外指针开销。

物资编号采用全局自增计数器（g_next_id）管理，初始值为1001。每次添加新物资时，将当前g_next_id作为新物资的编号，然后g_next_id递增1。关键点在于：g_next_id的值需要在程序重启后保持不变，否则新物资的编号会与已有物资冲突。解决方案是在materials.dat文件的第一行单独保存g_next_id的当前值，每次保存时写入、加载时读取，实现编号序列的持久化。

文件持久化采用文本文件格式而非二进制格式，主要考虑是课程设计场景下数据量不大，文本格式便于调试查看和手动修改，且「|」分隔的字段格式兼顾了可读性与解析效率。四个数据文件（users.dat、materials.dat、inbound.dat、outbound.dat）分别在对应数据变更后立即写入，以牺牲少量性能换取数据安全性。虽然这不是真正的事务机制，但对于课程设计规模的应用场景已足够可靠。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 字段长度限制宏 ---*/
#define MAX_NAME     64      /* 物资名称、用户名等字段的最大长度 */
#define MAX_SPEC     64      /* 规格型号字段的最大长度           */
#define MAX_UNIT     16      /* 计量单位字段的最大长度           */
#define MAX_USER     32      /* 用户名最大长度                   */
#define MAX_PASS     64      /* 密码最大长度                     */
#define MAX_DATE     16      /* 日期字符串最大长度（YYYY-MM-DD） */

/*--- 数据文件路径宏 ---*/
#define FILE_USERS   "users.dat"      /* 用户数据文件 */
#define FILE_MAT     "materials.dat"  /* 物资数据文件 */
#define FILE_IN      "inbound.dat"    /* 入库记录文件 */
#define FILE_OUT     "outbound.dat"   /* 出库记录文件 */
/*--- 用户信息节点（单链表）---*/
typedef struct UserNode {
    char username[MAX_USER];   /* 用户名，作为唯一标识     */
    char password[MAX_PASS];   /* 密码（明文存储）         */
    struct UserNode *next;     /* 链表指针                 */
} UserNode;

/*--- 物资信息节点（单链表）---*/
typedef struct MaterialNode {
    int  id;                   /* 物资编号（系统自增）     */
    char name[MAX_NAME];       /* 物资名称                 */
    char spec[MAX_SPEC];       /* 规格型号                 */
    char unit[MAX_UNIT];       /* 计量单位                 */
    int  stock;                /* 当前库存量               */
    struct MaterialNode *next;  /* 链表指针                 */
} MaterialNode;
```

## 5. 总结

本次课程设计实现了一个功能完整的仓库管理信息系统，完成了用户登录验证、物资信息的增删改查、物资入库与出库操作、出入库记录管理、库存总览与预警以及文本文件持久化存储等全部功能。系统代码组织清晰、注释详尽（总计约500行，含大量设计说明注释），采用模块化设计思想，划分为工具函数、用户管理、物资管理、入库管理、出库管理、库存查询和主控模块七大模块，各模块职责单一、耦合度低。

系统在技术实现上有以下亮点：其一，采用四条独立单链表管理四类数据实体，设计模式统一且清晰；其二，全局自增编号计数器g_next_id的持久化方案（materials.dat首行存储）巧妙解决了链表无天然下标时的编号管理问题；其三，出库操作的库存校验机制保证了系统中不会出现负库存的非法状态；其四，首次运行自动加载测试数据的设计提升了用户体验，便于快速验证系统功能。

在技术实现方面，深入理解了单链表数据结构在实际业务中的应用场景和设计权衡——选择单链表而非静态数组/双向链表，是基于「物资种类数量不确定」和「以尾部追加和顺序遍历为主」两个核心特征做出的合理决策。掌握了C语言链表操作的完整技能，包括节点创建、头插/尾插、按值删除（前驱指针法）、遍历查找等核心操作，以及内存分配（malloc）与释放（free）的正确配对方法。

通过文件持久化模块的实现，掌握了文本文件的格式化读写（fprintf/fscanf）技术，理解了「全量写入」策略的优缺点及其适用场景。库存预警功能的实现巩固了线性遍历筛选的应用方法。总体而言，本次课程设计将数据结构理论知识与实际业务场景紧密结合，对C语言编程、模块化设计、错误处理策略和防御性编程有了更深层次的理解和实践经验。
