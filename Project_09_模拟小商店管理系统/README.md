## 1. 需求分析

### 1.1 项目背景

在小型零售商店的日常经营中，店主需要管理多种商品的进货、库存和销售信息。传统的手工记账方式存在效率低下、容易出错、难以统计分析等问题。特别是当商品种类和供应商数量增多时，手工管理难以快速识别畅销品、评估各供应商的供货质量、以及准确计算盈亏状况，严重影响经营决策的科学性和及时性。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的模拟小商店管理系统。系统基于单链表数据结构组织货品信息，支持进货录入、卖货核减库存、库存查询等基本操作，并提供按销售率排序供应商、筛选高销量商品、统计总利润等高级分析功能。数据通过纯文本文件持久化存储，确保经营数据不丢失。系统模拟了真实零售场景中的核心业务流程，为用户提供了便捷的商品管理和经营分析工具。

### 1.2 功能需求

| 序号 | 功能模块 | 说明 |
|:---:|:---|:---|
| 1 | 进货管理 | 交互式录入，编号唯一性+数值合法性双重校验 |

## 2. 概要设计

### 2.1 数据结构设计

系统选择单链表作为核心数据结构，基于以下设计考量：货品数量动态变化（进货时增加、不设上限），链表的动态内存分配天然支持按需扩展，无需预分配固定容量。卖货操作需先按编号查找目标货品（线性搜索O(n)），然后直接修改节点的sold_qty字段（O(1)），无需删除节点。链表采用尾插法（insert_node遍历到尾部再追加），保持节点顺序与录入顺序一致，方便按时间顺序展示货品信息。

每个节点使用固定大小的字符数组（而非动态char*指针）存储字符串字段，原因是：(1) 简化内存管理，避免频繁的malloc/free操作；(2) 序列化到文件时直接将字段按格式输出，无需处理指针间接引用；(3) 课程项目中数据量有限，固定50字节的名称和厂家缓冲区完全满足需求。所有字符串复制使用strncpy+手动补'\0'的安全模式，有效防止缓冲区溢出。进货属性和销售数据合并在同一结构体中，库存通过减法实时计算，避免了数据冗余。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 缓冲区大小常量 ---*/
#define MAX_NAME_LEN    50          /* 货品名称最大长度          */
#define MAX_ID_LEN      20          /* 货品编号最大长度          */
#define MAX_FACTORY_LEN 50          /* 厂家名称最大长度          */
#define MAX_DATE_LEN    20          /* 日期字符串最大长度        */
#define MAX_ITEMS       200         /* 统计临时数组最大容量      */

/*--- 文件路径常量 ---*/
#define DATA_FILE       "goods.txt"             /* 主数据文件名     */
#define SORT_FILE       "sort_by_sales.txt"     /* 排序输出文件名   */
typedef struct GoodsNode {
    /*--- 基本属性 ---*/
    char    name[MAX_NAME_LEN];         /* 货品名称（可重复）   */
    char    id[MAX_ID_LEN];             /* 货品编号（全局唯一） */
    char    factory[MAX_FACTORY_LEN];   /* 厂家/供应商名称      */
    char    date[MAX_DATE_LEN];         /* 进货日期 YYYY-MM-DD  */

    /*--- 价格信息 ---*/
    double  purchase_price;             /* 进价（元）           */
    double  sell_price;                 /* 售价（元）           */

    /*--- 数量信息 ---*/
    int     purchase_qty;               /* 进货数量（总进货量） */
    int     sold_qty;                   /* 已卖出数量（动态累加）*/

    /*--- 链表指针 ---*/
    struct  GoodsNode *next;            /* 指向下一个货品节点   */
} GoodsNode;
```

## 5. 总结

本次课程设计实现了一个功能完整的模拟小商店管理系统，完成了进货管理和卖货管理的核心业务流程，支持库存实时查询、同名商品按销售率对比厂家、高销量商品筛选和总利润统计等增值分析功能，并通过文件I/O实现了数据的持久化存储。系统代码组织清晰、注释详尽（单行注释覆盖率超过40%），采用了模块化的设计思想，各功能函数职责单一、耦合度低。

在技术实现方面，深入理解了单链表数据结构在实际零售业务中的应用，掌握了malloc/free的动态内存管理技巧和安全字符串复制模式（strncpy+手动补终止符），巩固了文件格式设计（管道符分隔）和sscanf格式限定符安全解析的相关知识。通过统计分析模块的指针数组排序技术，理解了「操作指针而非数据」的优化思想。使用静态全局变量和static函数限制的作用域管理，体现了良好的代码封装实践。

### 改进方向

- **库存预警**: 增加低库存阈值预警，主菜单提示补货
- **购物车功能**: 引入购物车链表支持批量结账
- **时间统计**: 按日/月/年维度生成销售报表
- **调价功能**: 支持动态调整商品售价
- **排序算法**: 改冒泡为快排或归并，提升大数据性能
- **数据安全**: 增加文件完整性校验（MD5）
