## 1. 需求分析

### 1.1 项目背景

随着城市化进程加快，房屋租赁市场日益活跃，中介公司和物业管理机构需要高效管理大量的房源信息和租客数据。传统的纸质登记或Excel表格方式在数据量增大时查询效率低下、数据关联困难、历史记录追踪不便，无法满足现代租赁管理的需求。特别是当房屋数量达到数百套、租客数量上千时，手工管理方式极易出现房源状态不同步、租约遗漏和统计错误等问题。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的租房信息管理系统。系统基于单链表数据结构，支持房屋信息管理(增删改查)、租客信息管理(增删改查)、租房签约与退房的完整业务流程以及制表符分隔文件持久化存储。系统通过外键关联建立Tenant→Rental→House的数据关系模型，保证数据的引用完整性和一致性。

### 1.2 功能需求

| 序号 | 功能模块 | 说明 |
|:---:|:---|:---|
| 1 | 房源管理 | 房屋信息录入、查询、修改、删除，含产权证号唯一性校验 |
| 2 | 租客管理 | 租客信息录入、查询、修改、删除，含身份证号唯一性校验 |
| 3 | 租房签约 | 七步业务验证流程，关联房屋-租客-合同三实体 |
| 4 | 退房操作 | 软删除合同记录，释放房屋空闲状态 |
| 5 | 文件持久化 | 制表符分隔.dat文本文件，退出自动保存 |
| 6 | 引用完整性 | 外键关联校验，有在租合同时拒绝删除 |
| 7 | 内置测试 | 5套房+5名租客+3条登记，覆盖多状态场景 |

## 2. 概要设计

### 2.1 数据结构设计

系统选择单链表作为核心数据存储结构，基于以下设计考量：租房管理系统的数据规模在运行前难以精确预估(房屋和租客随时增减)，链表天然支持动态增长，无需预设容量上限(静态数组必须通过宏定义固定容量)。链表的插入操作为O(1)(头插法)或O(n)(尾插法，本系统采用后者以保持录入顺序)，删除操作为O(n)。对于课程项目的数据规模(通常数百条记录)，顺序遍历性能完全可接受。三条全局链表(g_houses/g_tenants/g_rentals)分别管理三类实体，通过certNo/idCard/contractNo字段进行跨链表关联，实现了简洁的关系模型。每个节点通过next指针串联，尾插法保证数据按录入时间排列，符合用户浏览预期。

系统在House结构体中采用冗余设计：通过isRented字段直接标记房屋租赁状态，虽然可以通过遍历Rental链表判断(需O(n)时间)，但冗余标记将查询降至O(1)，以空间换时间。房屋和租客的创建使用工厂函数(createHouse/createTenant/createRental)，统一内存分配和初始化流程。字符串拷贝使用strncpy+手动\0终止符确保缓冲区安全。删除操作采用前驱-当前双指针法，标准链表中途删除模式。文件持久化采用制表符分隔的纯文本格式(.dat)，%[^\t]格式说明符正确解析含空格的地址、备注等字段，优于CSV格式(CSV中的逗号可能与字段内容冲突)。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 字符串最大长度 ---*/
#define MAX_STR      128              /* 所有字符串字段统一缓冲区 */

/*--- 持久化文件名定义 ---*/
#define FILE_HOUSE   "houses.dat"     /* 房屋数据文件(制表符分隔) */
#define FILE_TENANT  "tenants.dat"    /* 租客数据文件(制表符分隔) */
#define FILE_RENTAL  "rentals.dat"    /* 租房登记数据文件(制表符分隔) */
typedef struct House {
    char address[MAX_STR];      /* 房屋地址 */
    char certNo[MAX_STR];       /* 房产证号(唯一标识) */
    char layout[MAX_STR];       /* 户型(如「两室一厅」) */
    double area;                /* 面积(平方米) */
    char decoration[MAX_STR];   /* 装修等级(简装/精装/豪装) */
    double monthlyRent;         /* 月租金(元) */
    int isRented;               /* 租赁状态：0=空闲，1=已租 */
    struct House *next;         /* 链表后继指针 */
} House;
```

## 5. 总结

本次课程设计实现了一个功能完整的租房信息管理系统，完成了房屋信息的增删改查、租客信息的增删改查、租房签约与退房的完整业务流程以及制表符分隔文件持久化存储等全部功能。系统代码组织清晰、注释详尽(总计约850行，每个函数均含Doxygen风格注释说明参数、返回值和设计思路)，采用模块化设计思想，划分为工具函数、房屋管理、租客管理、租房登记、文件持久化、内存管理和菜单界面七个模块，各模块职责单一、耦合度低。

在技术实现方面，深入理解了单链表数据结构在实际业务中的应用，掌握了尾插法(保持录入顺序)、前驱-当前双指针删除法、工厂函数(Factor Method)创建模式等链表操作的核心技术。业务层面理解了外键关联(Tenant→idCard→Rental→certNo→House)建立关系模型的方法，掌握了引用完整性校验(删除前检查活跃合同)和软删除(active=0保留历史)的数据管理策略。通过文件持久化模块理解了制表符分隔文本格式的读写方法，fscanf返回值的严格校验(==7/==6)保证了文件格式损坏时的容错能力。通过本次实践，对C语言中链表的malloc/free管理、strncpy安全字符串操作、和fgets/scanf混合使用的输入缓冲管理有了更深层次的理解。

### 改进方向

- **isRented冗余字段**: 废除冗余，统一遍历Rental链表判断状态
- **查找O(n)性能瓶颈**: 引入哈希表支持O(1)按产权号/身份证号查找
- **缺少退房时间记录**: 增加checkOut字段和自动租期/总租金计算
- **文本格式可扩展性**: 改用JSON格式支持字段增减不影响解析
- **缺少统计分析**: 增加区域空置率/历史记录/租金区间/时段筛选等统计
- **纯文本交互界面**: 引入ANSI颜色码和长列表分页浏览功能
- **输入格式未校验**: 增加日期/手机号正则表达式格式验证
