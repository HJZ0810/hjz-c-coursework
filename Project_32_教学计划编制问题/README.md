## 1. 需求分析

### 1.1 项目背景

在高等院校的教学管理中，每学期都需要为本专业学生制定科学合理的教学计划。然而，大学课程之间存在复杂的先修依赖关系——例如学生必须学完〈程序设计基础〉和〈离散数学〉后才能修读〈数据结构〉，学完〈数据结构〉和〈计算机原理〉后才能修读〈编译原理〉。课程数量越多，依赖关系越复杂，手工编排教学计划不仅耗时耗力，还容易违反先修约束或导致学期间负载严重失衡。

本项目运用图论中的AOV网模型解决这一实际问题。AOV网用顶点表示课程（活动），用有向边表示课程之间的先修关系（先行约束），将教学计划编制问题转化为在AOV网上进行拓扑排序的问题。系统通过邻接矩阵存储图结构，实现了基于贪心策略的自动排课算法，支持两种不同的编排目标：各学期负担尽量均匀（策略A）和课程尽量集中在前几个学期（策略B），满足不同教学理念的需求。系统还提供了环检测功能，防止因先修关系配置错误导致无法生成合法的教学计划。

## 2. 概要设计

### 2.1 数据结构设计

系统选择AOV网（邻接矩阵存储）+ 单链表作为核心数据结构。选择邻接矩阵存储课程间的有向边关系（adj[i][j]=1表示课程i是课程j的先修课），原因是：课程数量上限50门，矩阵仅需50×50×4=10KB内存，完全可接受；查询两点间是否有边的时间复杂度O(1)，拓扑排序中需要频繁查询入度和出边，邻接矩阵远优于邻接表。先修关系在各课程内部以单链表存储（PrereqNode），头插法插入时间复杂度O(1)，不同课程先修课数量差异大（0~5门），链表避免数组的空间浪费。

排课结果使用二维数组semester_courses[MAX_SEMESTERS][MAX_COURSES]存储——行索引对应学期，每行存储该学期安排的课程在全局courses[]数组中的索引值，避免冗余存储课程数据。配套semester_count[]和semester_credits[]数组记录每学期课程数和学分，用于贪心策略的负载判断。选择静态数组而非动态分配，是因为教学计划系统的课程数通常有限（50门以内），静态数组足以覆盖需求，且避免了动态内存管理的复杂性和潜在的内存泄漏风险。

## 5. 总结

本次课程设计运用AOV网和拓扑排序算法成功解决了一个实际应用问题——高等院校教学计划的自动编制。系统将课程间的先修约束建模为有向无环图，通过基于入度递推的拓扑排序算法自动生成满足所有先修约束的教学计划，并提供了负担均匀和集中排课两种编排策略供选择。算法在12门计算机专业核心课程上验证了正确性和有效性。

在技术实现方面，掌握了图论中AOV网的概念和拓扑排序算法的原理及实现，理解了邻接矩阵存储图结构在边查询效率上的优势（O(1) vs 邻接表O(n)），实践了贪心策略在资源分配问题中的应用。通过将课程和先修关系分别用Course结构体和PrereqNode链表表示、排课结果用Schedule二维数组存储的设计，实现了数据和逻辑的解耦，代码结构清晰、注释详尽。动态内存管理（malloc/free）和文件持久化的实践也进一步巩固了C语言基础。

### 改进方向

- **重复代码**: 提取公共逻辑到通用函数，减少两个策略的代码重复
- **O(n?)入度计算**: 缓存入度，增量更新
- **学分超限失败提示**: 建议调整参数或逐学期放宽上限
- **终端界面**: 增加颜色标识，初次自动加载测试数据
- **排课报告可视化**: 终端学分分布柱状图
- **硬约束扩展**: 支持教师/教室/时间冲突等更多约束
