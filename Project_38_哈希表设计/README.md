## 1. 需求分析

### 1.1 项目背景

哈希表（Hash Table）是一种高效的数据结构，通过哈希函数将键（Key）映射到数组中的位置，实现O(1)平均时间复杂度的查找、插入和删除操作。然而，由于哈希函数的多对一特性，不同键可能映射到相同位置，这就是哈希冲突。哈希冲突的处理方式直接影响哈希表的性能，常见的策略包括开放地址法（再探测法）和链地址法（分离链接法）。

本项目针对中国姓名拼音数据设计哈希表，要求实现完整的建表、查表、删表功能，并满足课程设计的性能指标要求（平均查找长度ASL≤2.0）。通过本项目的实践，深入理解哈希函数设计原理、冲突处理策略的选择、以及哈希表的性能分析方法。

## 2. 概要设计

### 2.1 数据结构设计

系统选择开放地址法作为哈希表实现方案，基于以下设计考量：数据量固定为30个测试人名，表大小41，定长数组设计无需动态内存管理，适合课程设计场景。开放地址法的优点是内存占用连续、缓存友好，缺点是删除操作复杂、需要探测。

三层抽象：SlotStatus枚举标记槽位生命周期三态（EMPTY→OCCUPIED→DELETED），HashSlot存储单个槽位的人名、状态、探测次数，HashTable管理槽位数组和全局统计量。

逻辑删除策略的必要性：在开放地址法中，探测链是解决冲突的关键。假设元素A与B发生冲突，B被存储在A的探测路径上。当删除A时，如果直接将A的槽位置为EMPTY，那么后续查找B时，探测链会在A的原位置终止（遇到EMPTY），导致B虽存在却无法被找到。引入DELETED状态，删除时仅标记为DELETED，不清空数据。查找时遇到DELETED继续探测，保证探测链完整性。新数据插入时可复用DELETED槽位。
