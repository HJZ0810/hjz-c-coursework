## 1. 需求分析

### 1.1 项目背景

在日常生活中，个人和企业都需要有效管理越来越多的联系人和社交关系信息。传统的纸质通讯录或Excel表格存在查找不便、容易丢失、难以分类等缺点，无法满足现代用户对联系人信息快速检索和灵活管理的需求。特别是在联系人数量增长时，手工管理方式效率极低且容易出错。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的通讯录管理系统。该系统基于单链表数据结构，支持联系人和分组的全生命周期管理，提供数据持久化存储能力，确保用户数据在程序退出后不会丢失。同时，系统提供了登录验证机制保障数据安全，以及模糊查询和统计汇总等辅助功能，全方位满足个人和小型团队的通讯录管理需求。

### 1.2 功能需求

| 序号 | 功能模块 | 说明 |
|:---:|:---|:---|
| 1 | 登录验证 | 3次重试机制，防止未授权访问 |
| 2 | 联系人添加 | 姓名/电话/邮箱/分组/地址 |
| 3 | 联系人显示 | 格式化表格全量展示 |

| 10 | 文件持久化 | contacts.dat + groups.dat |
| 11 | 内置数据 | 5分组+20联系人 |

## 2. 概要设计

### 2.1 数据结构设计

系统选择单链表作为核心数据结构，基于以下设计考量：通讯录数据量动态变化、增删操作频繁，链表的插入和删除操作时间复杂度为O(1)（已知位置）或O(n)（需查找），优于数组的O(n)移动开销；链表无需预分配固定大小，可按需动态扩展，适应数据量的不确定性。两个独立的链表（Contact链表和Group链表）通过分组名称进行逻辑关联，实现了松耦合的数据组织方式。

每个节点使用固定大小的字符数组（而非动态char*指针）存储字段数据，原因是：(1) 简化内存管理，避免频繁的malloc/free操作；(2) 序列化/反序列化到文件更加直接；(3) 课程项目中数据量有限，空间浪费在可接受范围内。节点分配使用calloc而非malloc，确保所有字符数组自动零初始化，保证字符串正确终止。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 缓冲区大小常量 ---*/
#define MAX_NAME     32      /* 姓名字段最大长度   */
#define MAX_PHONE    20      /* 电话字段最大长度   */
#define MAX_EMAIL    48      /* 邮箱字段最大长度   */
#define MAX_GROUP    24      /* 分组名字段最大长度 */
#define MAX_ADDR     64      /* 地址字段最大长度   */

/*--- 文件路径常量 ---*/
#define DATA_FILE    "contacts.dat"   /* 联系人数据文件 */
#define GROUP_FILE   "groups.dat"     /* 分组数据文件   */

/*--- UI 相关常量 ---*/
#define LINE_LEN     80               /* 终端分隔线字符数 */
typedef struct Contact {
    char name[MAX_NAME];        /* 姓名           */
    char phone[MAX_PHONE];      /* 电话           */
    char email[MAX_EMAIL];      /* 邮箱           */
    char group[MAX_GROUP];      /* 所属分组       */
    char address[MAX_ADDR];     /* 地址           */
    struct Contact *next;       /* 链表后继指针   */
} Contact;
```

## 5. 总结

本次课程设计实现了一个功能完整的通讯录管理系统，完成了联系人管理和分组管理的全套CRUD操作，支持模糊查询、统计汇总、登录验证等实用功能，并通过文件I/O实现了数据持久化存储。系统代码组织清晰、注释详尽，采用了模块化的设计思想，各模块职责单一、耦合度低。

在技术实现方面，深入理解了单链表数据结构在实际业务中的应用，掌握了malloc/calloc/free的动态内存管理技巧，巩固了文件读写和字符串处理的相关知识。通过本次实践，对指针操作、内存安全和数据结构设计有了更深层次的理解。

### 改进方向

- **密码明文硬编码**: 使用哈希存储，增加多用户
- **单链表删除效率**: 改用双向链表或跳表
- **分组字符串匹配**: 改用ID关联提升效率
- **终端界面简单**: 增加彩色输出和富交互
- **文件格式固定**: 改用JSON或SQLite
