## 1. 需求分析

### 1.1 项目背景

图（Graph）是计算机科学中最基础也最重要的数据结构之一，广泛应用于社交网络分析、路径规划、电路设计、编译原理等领域。图的存储方式直接决定了相关算法的实现效率和代码复杂度。常见的图存储结构有邻接矩阵（Adjacency Matrix）、邻接表（Adjacency List）、十字链表、邻接多重表和边集数组等，其中前两种是最基本、最常用的存储方式。

本课程设计旨在通过C语言实现图的多种存储结构及其相互转换，深入理解两种经典存储方式的内存布局、时空复杂度和适用场景。通过构建完整的转换算法和文件持久化系统，使学习者掌握：(1) 邻接矩阵 O(V?) 空间 vs 邻接表 O(V+E) 空间的本质区别；(2) 有向图与无向图在两种存储结构中的处理差异；(3) 动态内存管理的正确方法（malloc/free）；(4) 转换算法背后等价变换的数学思想。本项目是对数据结构课程中"图"章节知识的综合实践。

## 2. 概要设计

### 2.1 数据结构设计

系统选用邻接矩阵和邻接表两种互补的存储结构。邻接矩阵适合稠密图（边数接近V?），判断邻接只需 O(1)，但空间固定为 O(V?)，无论实际边数多少都占用相同空间。邻接表适合稀疏图（边数远小于V?），空间仅为 O(V+E)，遍历某顶点的邻接点高效，但判断两顶点是否邻接需遍历链表 O(degree(v))。两种结构通过转换算法实现等价变换，使用者可根据具体应用场景选择合适结构。

邻接表的边链表采用单链表+头插法实现。选择头插法而非尾插法的原因是：(1) 头插法只需修改两个指针（新节点→原头→更新头指针），时间复杂度 O(1)；(2) 尾插法需要遍历到链表尾部 O(degree(v))；(3) 边的插入顺序不影响图的无序集合语义。边节点使用 malloc 动态分配，程序退出前通过遍历链表逐一 free 释放，遵循"谁分配谁释放"的内存管理黄金法则。顶点数组使用静态分配（MAX_VERTEX=100），在灵活性和复杂度之间取得了平衡。

## 5. 总结

本次课程设计实现了一个功能完整的图的存储与相互转换系统，涵盖了邻接矩阵和邻接表两种经典图存储结构的完整生命周期管理（创建、显示、转换、保存、加载）。系统支持四种图类型组合，提供了11项菜单功能，内置4组测试数据验证了核心转换算法的正确性。代码组织结构清晰，注释详尽，每个函数都有功能说明、算法分析、时间复杂度标注和设计考量说明。

在技术实现方面，通过本项目深入理解了：(1) 邻接矩阵 O(V?) 空间 vs 邻接表 O(V+E) 空间的本质区别及适用场景，(2) 有向图与无向图在两种存储结构中的处理差异（矩阵对称性、邻接表双向存储），(3) 头插法建链表的 O(1) 插入优势，(4) 动态内存管理中 malloc/free 的正确使用和"谁分配谁释放"的原则，(5) 文件持久化中自描述格式设计的方法。两种存储结构的双向转换算法本质上是对同一图信息的等价变换，这一思想是图论算法设计的基础。

### 改进方向

- **存储结构**: 增加十字链表(有向图)/邻接多重表(无向图)
- **边集数组**: 增加EdgeSet支持，实现三结构完整互转矩阵
- **转换优化**: 稀疏矩阵扫描时提前剪枝跳过全零行
- **文件格式**: 增加JSON支持，提升跨平台数据交换能力
- **图算法**: 扩展DFS/BFS/最短路径/最小生成树等算法
- **内存管理**: 引入内存池管理ArcNode分配回收
