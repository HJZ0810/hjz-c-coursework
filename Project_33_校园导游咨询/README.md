## 1. 需求分析

### 1.1 项目背景

随着高校校园规模的不断扩大，来访客人、新生入学、老生离校等各类人群对校园地理信息的需求日益增长。传统的问路方式效率低下，且依赖于问询对象对校园的熟悉程度。开发一套校园导游咨询系统，通过数字化方式提供景点信息查询和最短路径导航服务，可以有效提升来访者的校园体验，减少问询工作人员的负担。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的校园导游咨询系统。该系统基于邻接矩阵存储校园无向网图，运用Dijkstra单源最短路径算法实现任意两景点间的最短路径计算，提供数据持久化存储能力，确保程序重启后数据不丢失。同时，系统提供了登录验证机制保障数据安全，以及ASCII平面图可视化功能，全方位满足来访客人和新生的校园导游咨询需求。

## 2. 概要设计

### 2.1 数据结构设计

系统选择邻接矩阵作为核心数据结构，基于以下设计考量：景点数量最多20个，空间占用为400个整数（约1.6KB），完全可接受；邻接矩阵查询任意两点间是否有边以及边的权重均为O(1)，适合路径规划场景；实现简洁直观，便于课程设计阶段展示和讲解。相比之下，邻接表虽空间利用率高，但查询两点间是否有边需要遍历链表，时间复杂度为O(V+E)，不利于最短路径计算。

每个景点信息使用固定大小字符数组（name[32]、desc[128]）存储字段数据，简化内存管理避免指针悬挂，使用定长缓冲区防止缓冲区溢出。邻接矩阵使用INT常量MAX_VERTEX=20作为维度上限，选择INF=99999而非INT_MAX作为无穷大标记，避免后续加法运算溢出。对角线元素为0表示顶点到自身距离为0，无边连接时为INF。

## 3. 详细设计

### 3.1 核心数据结构

```c
#define MAX_VERTEX   20       /* 最大景点数量，决定邻接矩阵维度上限 */
#define MAX_NAME     32       /* 景点名称最大字节数（含\0结束符） */
#define MAX_DESC     128      /* 景点简介最大字节数（含\0结束符） */
#define INF          99999    /* 无穷大标记：表示两景点间无直接路径 */
                             /* 选择99999而非INT_MAX避免加法溢出 */
#define DATA_FILE    "campus_data.txt"  /* 数据持久化文件路径 */
/*--- 景点信息结构体 ---*/
typedef struct {
    int  id;                  /* 景点唯一编号（从1开始，连续编号） */
    char name[MAX_NAME];      /* 景点名称字符串               */
    char desc[MAX_DESC];      /* 景点简介字符串               */
} ScenicSpot;
```

## 5. 总结

本次课程设计实现了一个功能完整的校园导游咨询系统，完成了基于邻接矩阵的校园无向网图存储、12个景点和22条路径的内置数据、Dijkstra单源最短路径算法的实现与调用、景点信息查询、最短路径导航、ASCII平面图可视化、用户登录验证和数据文件持久化存储等全套功能。系统代码组织清晰、注释详尽，采用模块化的设计思想，各模块职责单一。

在技术实现方面，深入理解了图数据结构的两种存储方式（邻接矩阵vs邻接表）的适用场景差异，掌握了Dijkstra算法从初始化到贪心选择、松弛操作再到路径回溯的完整执行流程，理解了O(V?)朴素实现与优先队列优化的取舍原则。通过本次实践，对图的建模、最短路径问题求解和工程化的代码组织有了更深入的理解。

### 改进方向

- **Dijkstra优化**: 朴素O(V?)→优先队列O((V+E)logV)
- **文件格式**: 文本→JSON/SQLite结构化格式
- **多用户**: 单账户→数据库+密码哈希+多角色
- **彩色UI**: ASCII字符→彩色终端+富交互
- **地图增强**: 固定ASCII→坐标映射+动态缩放+导出图片
