## 1. 需求分析

### 1.1 项目背景

随着高校招生规模逐年扩大，学生宿舍的信息化管理需求日益迫切。传统的手工登记方式不仅效率低下、容易出错，还无法实现跨业务模块的数据联动——例如宿舍分配后需人工同步床位计数，退房后难以追溯历史记录，报修进度跟踪分散在多张纸质表格中。这不仅增加了管理人员的工作负担，也影响了学生的服务体验。

本系统从实际业务场景出发，以「宿舍编号」为数据锚点，将宿舍、学生、卫生、水电、报修、访客六类实体通过单链表组织起来，实现了多模块间的数据关联与协同管理。系统覆盖了学生从入住到退房的完整生命周期，以及宿舍从分配到日常维护的全流程信息化，有效解决了高校宿舍管理中的信息孤岛和数据一致性问题。

### 1.2 功能需求

| 序号 | 功能模块 | 说明 |
|:---:|:---|:---|
| 1 | 宿舍信息管理 | 宿舍编号、楼栋、楼层、床位数的增删改查，删除前校验是否有学生入住 |
| 2 | 学生入住管理 | 入住登记、退房处理、缴费管理，自动维护床位占用计数和退房日期 |
| 3 | 卫生检查管理 | 检查评分录入、等级自动判定（优秀/良好/合格/不合格）、按宿舍分组统计平均分 |
| 4 | 水电收费管理 | 水电费按宿舍+月份录入、缴纳状态跟踪、记录汇总查看 |
| 5 | 报修管理 | 报修提交（自动编号）、状态流转（待处理→处理中→已完成）、全流程跟踪 |
| 6 | 外来人员管理 | 来访登记（自动记录时间）、离开登记、在访状态监控 |
| 7 | 查询统计 | 系统数据总览（在住人数、未缴费数、待处理报修等）、按宿舍一站式综合查询 |

## 2. 概要设计

### 2.1 数据结构设计

系统采用单链表作为核心数据存储结构，六类业务实体（宿舍、学生、卫生检查、水电收费、报修、访客）各自维护一条独立链表，通过全局头指针统一管理。选择单链表而非数组的原因在于：课程项目数据规模为百级，链表的遍历开销完全可忽略，而链表的动态增删能力避免了预分配固定容量的问题——宿舍可以随时新增，学生随时入住和退房，无需担心数组空间不足或浪费。

文件持久化采用空格分隔的纯文本格式（.dat文件），而非二进制存储。这一设计决策源于课程项目的实际需求：文本格式便于调试时直接用编辑器查看数据内容，也方便人工校验和修正；同时，fprintf/fscanf的文本读写函数使用门槛低，降低了同学的代码理解成本。数据保存采用「变更即保存」策略——每次增删改操作完成后立即将整条链表写入文件，而非等到程序退出时统一保存。虽然牺牲了少量I/O性能，但能有效防止因终端窗口被直接关闭而导致的内存数据丢失，在稳定性要求高于性能的场景下是合理的选择。最后，学生退房采用逻辑删除模式：设置check_out日期字段而非从链表中物理删除节点，这样既能保留完整的历史入住记录，又允许学生再次入住（通过查询check_out字段判断是否在住）。

### 2.2 系统架构

### 2.3 模块划分

| 模块 | 功能 |
|:---|:---|
| 宿舍信息管理 | 宿舍的增删改查，包括按编号精确查询、删除前入住校验、修改时选择性更新 |
| 学生入住管理 | 入住登记（宿舍编号+学号双重校验）、缴费确认、退房处理（自动日期+床位计数） |

| 水电收费管理 | 按宿舍+月份录入水电费、按复合键查找并缴纳、记录汇总查看 |
| 报修管理 | 自动分配编号提交报修、状态三级流转更新（待处理/处理中/已完成）、全量记录查看 |
| 外来人员管理 | 来访登记（自动精确到分钟的时间戳）、离开登记更新、在访人员状态跟踪 |

## 3. 详细设计

### 3.1 核心数据结构

```c
#define MAX_STR      64       /* 通用字段缓冲区（姓名、编号等短文本）        */
#define MAX_DESC     256      /* 描述性文本缓冲区（备注、问题描述等长文本）   */

#define DATA_DIR     "data/"                    /* 数据文件根目录             */
#define FILE_ROOM    "data/rooms.dat"           /* 宿舍信息持久化文件         */
#define FILE_STU     "data/students.dat"        /* 学生入住记录持久化文件     */
#define FILE_HYGIENE "data/hygiene.dat"         /* 卫生检查记录持久化文件     */
#define FILE_UTILITY "data/utility.dat"         /* 水电收费记录持久化文件     */
#define FILE_REPAIR  "data/repair.dat"          /* 报修记录持久化文件         */
#define FILE_VISITOR "data/visitor.dat"         /* 外来人员登记持久化文件     */
typedef struct Room {
    char id[MAX_STR];          /* 宿舍编号，全局唯一，如 A101、B201      */
    char building[MAX_STR];    /* 所属楼栋名称，如 北苑、南苑            */
    int  floor;                /* 楼层号（正整数）                        */
    int  capacity;             /* 总床位数（四人间=4，六人间=6）          */
    int  occupied;             /* 当前已入住人数（入住+1，退房-1）        */
    char type[MAX_STR];        /* 房间类型描述，如 四人间、六人间         */
    struct Room *next;         /* 链表后继指针（尾节点指向 NULL）         */
} Room;
```

## 5. 总结

本项目从需求分析到编码实现，完整构建了一个基于C99单链表的学生宿舍管理信息系统。系统覆盖宿舍全生命周期管理（创建→入住→日常维护→退房），通过六大业务模块（宿舍管理、入住管理、卫生检查、水电收费、报修管理、访客登记）和查询统计模块，形成了完整的数据闭环。在数据结构设计上，选择单链表作为核心存储方案，充分发挥了链表动态扩容的优势，以头插法实现O(1)插入效率。系统内置了充分的测试数据集（10间宿舍、8名学生、7条卫生记录等），无需手动录入即可开箱即用地体验全部功能。

在工程实践层面，本项目运用了多项经典C语言编程技巧：二级指针法统一处理链表删除的两种边界情况、占位符（-）配合fscanf实现文本文件中空字段的存储与恢复、自增编号计数器在程序启动时扫描文件恢复最大值以避免ID冲突、以及变更即保存策略确保数据的可靠持久化。代码注释率较高（超过40%），每个结构体、函数、关键算法决策均有详细注释说明设计意图和权衡考量，适合作为C语言数据结构课程设计的教学参考案例。

### 改进方向

- **数据存储**: 将文本文件存储升级为SQLite或MySQL数据库，大幅提升查询效率和数据安全性
- **并发访问**: 增加多线程支持，支持多个管理员同时操作不同模块，提高系统并发处理能力
- **图形界面**: 将命令行界面升级为GUI（Qt/GTK+），降低非技术用户的使用门槛
- **权限控制**: 引入角色权限管理（管理员/操作员/查询员），不同角色访问不同菜单和功能
- **数据校验**: 增加身份证号格式校验、学号规则校验、日期格式自动校验等业务级输入验证
- **统计报表**: 增加ECharts可视化图表（入住率趋势、卫生评评分对比、水电费同比分析等）
