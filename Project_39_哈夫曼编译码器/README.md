## 1. 需求分析

### 1.1 项目背景

在现代信息社会中，数据传输和存储的效率至关重要。哈夫曼编码（Huffman Coding）是一种基于字符出现频率的最优前缀编码方法，广泛应用于数据压缩领域（如ZIP、JPEG、MP3等格式）。它通过为高频字符分配较短的编码、为低频字符分配较长的编码，使得整体编码长度最短，从而实现无损数据压缩。

本项目旨在运用C语言和数据结构知识，设计并实现一个完整的哈夫曼编/译码系统。该系统基于贪心算法构建哈夫曼树，生成字符的最优前缀编码，支持将源文本编码为比特流，并能将比特流准确译码还原为原文。系统采用静态数组存储哈夫曼树，通过文件I/O实现编码数据的持久化，同时提供树形结构可视化功能，全方位展示哈夫曼树的构建结果和编码原理。

## 2. 概要设计

### 2.1 数据结构设计

系统选择静态数组存储的哈夫曼树作为核心数据结构，基于以下设计考量：哈夫曼树的节点数在编译时即可确定（2n-1个节点，n为字符集大小），使用静态数组无需动态内存分配，简化了内存管理；数组下标从1开始（而非0），使得parent/lchild/rchild为0时可以自然地表示'不存在'的语义，避免了下标判断的复杂性；存储布局上，下标[1..n]为叶子节点（存储字符及权值），下标[n+1..2n-1]为内部节点（权值为左右孩子权值之和），下标2n-1为根节点。

每个节点使用固定大小的字符数组存储编码（而非动态char*指针），原因是：(1) 哈夫曼编码的最大长度在树高可控范围内，固定大小简单高效；(2) 序列化/反序列化到文件更加直接；(3) 课程项目中字符集有限（≤30），空间浪费在可接受范围内。Select算法采用线性扫描查找权值最小的两个无父节点，时间复杂度O(n?)，对于小规模字符集完全足够；若需优化可使用最小堆降至O(n log n)。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 缓冲区大小常量 ---*/
#define MAX_CHARS   30          /* 字符集最大容量（最多30个不同字符） */
#define MAX_CODELEN 50          /* 单个字符哈夫曼编码的最大长度（比特数） */
#define MAX_TEXT    1024        /* 源文本/译码文本最大长度（字符数）     */
#define MAX_CODEBUF 8192        /* 编码比特流缓冲区最大长度（比特数）    */
#define LINE_WIDTH  50          /* 打印代码文件时每行显示的比特数        */
#define LOGIN_USER  "admin"    /* 系统登录用户名                      */
#define LOGIN_PASS  "123456"   /* 系统登录密码                        */
typedef struct {
    int  weight;        /* 节点权值：叶子为字符频度，内部为左右权值之和 */
    int  parent;        /* 父节点下标，0表示无父节点                   */
    int  lchild;        /* 左孩子下标，0表示无左孩子（叶子）           */
    int  rchild;        /* 右孩子下标，0表示无右孩子（叶子）           */
    char ch;            /* 对应字符（仅叶子节点有效）                   */
} HTNode;
```

## 5. 总结

本次课程设计实现了一个功能完整的哈夫曼编/译码系统，完成了哈夫曼树的构建、编码、译码、代码文件打印和树可视化等全套功能，支持默认和自定义两种权值方案，并通过文件I/O实现了数据的持久化存储。系统代码组织清晰、注释详尽，采用了模块化的设计思想，各模块职责单一、耦合度低。

在技术实现方面，深入理解了哈夫曼树和最优前缀编码的原理，掌握了贪心算法在数据压缩中的应用，巩固了静态数组存储、文件读写和字符串处理的相关知识。通过本次实践，对树结构的遍历（回溯建编码、下行译码）、递归可视化等算法有了更深层次的理解，提升了C语言编程能力和系统工程化思维。

### 改进方向

- **Select算法效率**: 改用最小堆优化至O(n log n)
- **编码存储方式**: 改为真正比特流(bit packing)
- **文件格式**: hfmTree改用二进制格式
- **多文件编码**: 扩展支持批量文件压缩
- **用户界面**: 增加彩色输出和富交互
