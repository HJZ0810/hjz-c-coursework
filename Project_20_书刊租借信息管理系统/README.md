## 1. 需求分析

### 1.1 项目背景

随着公共图书馆、高校资料室以及私人书吧等场所规模的扩大，传统的手工记录书刊借阅信息的方式已难以满足业务需求。手工管理存在效率低下、容易出错、数据统计困难、无法实现多用户并发访问等问题。为了提高书刊租借业务的管理效率，减少人工操作错误，实现租借信息的实时查询与统计分析，开发一套书刊租借信息管理系统具有重要的实际意义。

本项目旨在设计并实现一个功能完善的命令行版书刊租借信息管理系统，通过C语言实现核心数据结构和文件持久化存储，帮助学生深入理解线性表的链式存储结构，掌握文件I/O操作技巧，并综合运用结构体、指针、函数封装等C语言核心知识点完成一个具有一定实用价值的完整系统。

### 1.2 功能需求

| 序号 | 功能模块 | 说明 |
|:---:|:---|:---|
| 1 | 读者信息管理 | 增删改查读者基本信息，身份证唯一标识，级联删除关联租书记录 |
| 2 | 书刊信息管理 | 增删改查书刊基本信息，ISBN唯一标识，支持ISBN精确查询和书名模糊查询 |
| 3 | 租书业务管理 | 租书、还书、删除/修改/查询租书记录，自动计算租金，恢复书刊状态 |
| 4 | 利润信息管理 | 按日期范围统计租金收入，按读者统计租书次数和累计租金 |
| 5 | 用户账号管理 | 注册、登录、密码修改、角色授权，基于RBAC的权限控制 |
| 6 | 数据持久化 | 文本文件存储，竖线分隔符格式，全局自增ID保证编号连续 |

## 2. 概要设计

### 2.1 数据结构设计

系统采用四条带头结点的单链表作为核心数据结构，分别维护读者信息、书刊信息、租书记录和用户账号。链表节点通过结构体定义，包含数据域和后继指针域。所有插入操作采用头插法实现O(1)时间复杂度，查找操作采用线性遍历O(n)时间复杂度，对于课程项目规模（几百条记录）完全满足性能需求。选择链表而非顺序表的原因在于：支持动态扩容避免固定数组容量限制，插入删除操作无需移动大量元素，代码实现更直观地体现数据结构思想。

租书记录链表采用全局自增ID作为记录编号的唯一标识，自增计数器在程序退出时写入文件首行，加载时优先恢复该值，确保重启后编号连续不重复。系统利用YYYY-MM-DD日期格式的字典序等于日期序的特性，在按日期范围统计租金时直接使用strcmp进行字符串比较，避免了复杂的时间戳转换计算。书刊的可租状态通过available字段与租书记录联动控制：租书时设为0，还书时恢复为1，删除租书记录时若状态为租出中则同步恢复书刊状态，保证数据一致性。

## 3. 详细设计

### 3.1 核心数据结构

```c
/* 通用字符串最大长度（姓名、书名等） */
#define MAX_STR      64
/* 身份证号码最大长度（含末尾 \0） */
#define MAX_ID       20
/* ISBN号码最大长度 */
#define MAX_ISBN     20
/* 电话号码最大长度 */
#define MAX_PHONE    16
/* 用户名最大长度 */
#define MAX_USERNAME 32
/* 密码最大长度 */
#define MAX_PASSWORD 32
/* 每日租金（元/天），全局统一费率 */
#define RENTAL_RATE  1.0f

/* 数据文件路径宏定义 */
#define FILE_READERS  "readers.dat"
#define FILE_BOOKS    "books.dat"
#define FILE_RENTALS  "rentals.dat"
#define FILE_USERS    "users.dat"
typedef struct ReaderNode {
    char id[MAX_ID];              /* 身份证号码（唯一标识，不可重复） */
    char name[MAX_STR];           /* 读者姓名 */
    char gender[8];               /* 性别：「男」或「女」 */
    char phone[MAX_PHONE];        /* 联系电话 */
    struct ReaderNode *next;      /* 链表后继指针，NULL表示链表末尾 */
} ReaderNode;
```

## 5. 总结

本项目成功实现了一个功能完整的书刊租借信息管理系统，通过单链表数据结构有效管理了读者、书刊、租书记录和用户账号四类核心数据。系统实现了从需求分析、概要设计、详细设计到编码实现的完整开发流程，培养了模块化程序设计的思维能力。

在实现过程中，深入理解了线性表的链式存储结构及其与顺序存储的优劣对比，掌握了文件I/O的文本模式读写技巧，实践了基于角色的访问控制（RBAC）权限管理模型。通过级联删除机制保证了关联数据的一致性，利用日期格式的字典序特性简化了范围查询逻辑。代码遵循C99标准，结构清晰，注释详尽，具备一定的工程规范意识。

### 改进方向

- **数据结构优化**: 引入哈希表或平衡二叉搜索树提升查找效率
- **超期罚款机制**: 添加租借期限字段，实现超期自动罚款
- **密码安全增强**: 使用bcrypt等算法哈希存储密码
- **输入验证强化**: 增加正则表达式校验，完善错误提示
- **界面交互优化**: 分页显示、颜色高亮、自动补全
