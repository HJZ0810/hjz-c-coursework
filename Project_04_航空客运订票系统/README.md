## 1. 需求分析

### 1.1 项目背景

航空客运订票是航空公司核心业务系统之一，需要高效管理航班信息、处理大量客户订票请求，并妥善处理满员航班时的候补排队问题。传统手工订票方式存在效率低、易出错、无法处理候补队列等缺陷，无法满足现代航空公司的运营需求。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的航空客运订票系统。系统采用顺序表存储航班、链表存储客户信息、链式队列管理候补名单的数据结构组合，既保证了查找效率，又实现了动态扩展。通过退票后自动处理候补队列的机制，实现了公平透明的订票服务，提升了客户体验。

## 2. 概要设计

### 2.1 数据结构设计

系统采用三种数据结构协同工作：

1. 航班顺序表（静态数组）：flights[]数组按航班号升序存储最多50条航班信息。顺序表设计使得：①按下标访问为O(1)随机访问；②顺序存储缓存友好；③为后续二分查找优化预留基础。不足在于插入/删除需要O(n)元素移动，但航班数量有限，该开销可接受。

2. 客户有序链表（单链表）：每个航班维护一条已订票客户链表，按姓名升序排列。有序链表使得：①遍历输出天然有序，无需额外排序；②插入操作在O(n)内完成且保证数据有序性；③删除操作灵活，无需移动元素。链表按姓名排序也便于用户按姓名查找客户。

3. 候补链式队列（链式队列）：每个航班维护一条等候替补队列，采用front/rear双指针实现FIFO。入队在rear端进行，出队在front端进行，两者均为O(1)。退票时自动从队头开始处理候补客户，保证先到先服务的公平性。队列空时front==rear==NULL，出队后队列变空需同步更新rear为NULL。

内存管理采用固定大小字符数组存储字段（而非动态char*指针），原因：①简化内存管理，避免频繁malloc/free；②序列化/反序列化到二进制文件更直接；③课程项目数据量有限，空间浪费可接受。节点分配使用malloc并配合strncpy复制字符串，同时手动设置字符串终止符，确保安全。

## 3. 详细设计

### 3.1 核心数据结构

```c
#define MAX_FLIGHTS      50    /* 航班最大数量 */
#define MAX_NAME_LEN     20    /* 姓名字段最大长度（19字符+终止符）*/
#define MAX_DEST_LEN     30    /* 终点站名字段最大长度 */
#define MAX_FLIGHT_NO    12    /* 航班号字段最大长度 */
#define MAX_PLANE_NO     12    /* 飞机号字段最大长度 */
#define DATA_FILE        "airline_data.dat"  /* 数据文件路径 */
typedef struct Flight {
    char dest[MAX_DEST_LEN];         /* 终点站名 */
    char flightNo[MAX_FLIGHT_NO];    /* 航班号（全局唯一）*/
    char planeNo[MAX_PLANE_NO];      /* 飞机注册号 */
    int  weekday;                    /* 飞行周日（1~7）*/
    int  capacity;                   /* 乘员定额（最大座位数）*/
    int  remaining;                  /* 当前余票量 */
    CustomerNode *customers;         /* 已订票客户有序链表 */
    WaitQueue    waitQueue;          /* 等候替补链式队列 */
} Flight;
```

## 5. 总结

本次课程设计实现了一个功能完整的航空客运订票系统，完成了航班管理、订票、退票、候补队列等全套业务功能。系统采用顺序表、链表、队列三种数据结构协同工作，深入理解了不同数据结构在实际业务场景中的应用。候补队列的自动处理机制体现了系统的智能化设计，提升了用户体验。

在技术实现方面，掌握了链式队列的FIFO特性及其入队出队操作，深入理解了有序链表按关键字排序的插入算法，巩固了文件二进制格式的读写技巧和动态内存管理经验。通过本次实践，对多种数据结构的组合应用和数据持久化有了更深入的认识。

### 改进方向

- **航班查找O(n)**: 扩展为二分查找O(log n)
- **座位管理粗粒度**: 细化到每座位状态，支持互换
