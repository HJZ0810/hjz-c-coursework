## 1. 需求分析

### 1.1 项目背景

图书馆作为知识传播的重要场所，其日常运营涉及图书采编、入库、借阅、归还、查询等大量业务流程。传统的手工记录方式效率低下，容易出现库存统计不准确、借阅记录丢失、超期无法追踪等问题。随着馆藏量增长，人工管理方式越来越难以满足精确化、实时化的管理需求。

本项目旨在运用C语言和数据结构知识，设计并实现一个功能完善的图书管理系统。系统采用两级嵌套链表结构，将图书信息与借阅记录进行逻辑关联但物理独立管理，实现了图书全生命周期管理（从采编入库到注销清除）和借阅状态流转（在馆→借出→归还）。同时通过文件I/O实现数据持久化，确保程序退出后数据不丢失，满足小型图书馆或个人藏书管理的实际需求。

## 2. 概要设计

### 2.1 数据结构设计

系统采用"链表+链表"的两级嵌套链表结构：Book节点通过next指针串联成主链表（由全局头指针g_head管理），每个Book节点又通过borrow_list指针挂载一条BorrowRecord子链表。这种设计将图书管理与借阅管理在逻辑上解耦——图书的增删不影响借阅记录的独立性，借阅记录的增删也不需要修改Book结构体本身（除stock字段外）。链表结构天然支持动态增删，无需预分配固定大小的数组，适合馆藏量不确定的场景。

节点分配统一使用calloc而非malloc，确保所有字符数组自动零初始化，避免未初始化字符串导致的未定义行为。链表插入策略采用尾部插入而非头部插入，虽然时间复杂度为O(n)，但保持了数据的录入顺序，便于人工核对。借阅记录的尾部插入同样保持了借阅时间顺序，使归还时的序号选择符合直觉。文件存储选择制表符(\t)作为分隔符而非空格，是因为书名和著者字段可能包含空格（如"Stuart Russell"），使用空格会导致解析歧义。

## 3. 详细设计

### 3.1 核心数据结构

```c
/*--- 字段最大长度（含'\0'终止符） ---*/
#define MAX_ID_LEN      32      /* 书号最大长度，兼容ISBN-13     */
#define MAX_TITLE_LEN   64      /* 书名最大长度                   */
#define MAX_AUTHOR_LEN  32      /* 著者最大长度                   */
#define MAX_TYPE_LEN    16      /* 类别最大长度                   */
#define MAX_CARD_LEN    20      /* 图书证号最大长度               */
#define MAX_DATE_LEN    12      /* 日期字符串长度，格式YYYY-MM-DD */

/*--- 文件路径常量 ---*/
#define DATA_FILE  "library.dat"   /* 数据持久化文件名           */
typedef struct BorrowRecord {
    char card_id[MAX_CARD_LEN];     /* 借阅者图书证号             */
    char due_date[MAX_DATE_LEN];    /* 归还期限 (YYYY-MM-DD)      */
    struct BorrowRecord *next;      /* 指向下一条借阅记录         */
} BorrowRecord;
```

## 5. 总结

本次课程设计实现了一个功能完整的图书管理系统，完成了图书采编入库、清除库存、借阅管理、归还管理等核心业务流程，支持三种查询方式和数据持久化存储。系统采用两级嵌套链表结构将图书信息与借阅记录解耦管理，代码组织清晰、注释详尽，采用了模块化设计思想，各模块职责单一、耦合度低。

在技术实现方面，深入理解了嵌套链表数据结构在实际业务中的应用，掌握了链表节点删除的双指针法、calloc零初始化的内存安全实践、制表符分隔的文件格式设计等工程技巧。通过借阅状态流转的设计，对数据一致性维护有了更深刻的认识——库存变化与借阅记录的创建/删除必须在同一事务内完成并立即持久化，防止数据不一致。

### 改进方向

- **仅精确匹配查询**: 增加书名模糊查询和作者查询
- **无超期检测**: 增加超期标记和提醒功能
- **线性查找O(n)**: 引入哈希表优化为O(1)
- **缺少图书修改**: 支持修改书名/著者等元数据
- **纯文本文件格式**: 改用JSON或SQLite
